## 2. コード品質・アーキテクチャ評価

### 良い点

| 観点 | 評価 |
|------|------|
| **単一責任原則** | `parser.ts` / `calculator.ts` / `formatter.ts` の 3 層分離が明確 |
| **型安全性** | TypeScript strict モード、verbatimModuleSyntax 有効、`import type` 徹底 |
| **テスト網羅性** | 18 テスト全通過（パーサ 11、フォーマッタ 7）、エッジケース含む |
| **エラー耐性** | `localStorage` / `crypto.randomUUID` / 入力バリデーション全て try-catch 保護 |
| **セキュリティ** | 外部 API 依存なし、XSS 対策（React 自動エスケープ）、CSP 互換ビルド |
| **アクセシビリティ** | `aria-label`、セマンティック HTML、フォーカス可視化、sr-only ラベル |

### 指摘事項（Medium / Low）

| ID | 重要度 | 箇所 | 内容 | 推奨アクション |
|----|--------|------|------|----------------|
| **Q-01** | Medium | `parser.ts:124` | `splitRecipeText` の分割正規表現に `個|本|束|丁|切れ|枚|かけ|片|袋|缶|房|玉|尾|滴|杯|把|株|粒|パック|瓶` が含まれるが、`formatter.ts` ではこれら助数詞単位を特別扱いせず「数値＋単位」として単純丸め表示のみ。仕様例に「個・本・枚等」を認識とあるが、計量しやすい整形はされない。 | 助数詞単位でも「1.5個 → 1個＋半分」等の表現整形を検討、または README/仕様で「g/ml/大さじ/小さじのみ整形」と明記 |
| **Q-02** | Medium | `formatter.ts:12-22` | 大さじ・小さじ変換で `totalTsp = Math.round(totalTsp * 100) / 100` の丸め後に `tsp = Math.round((totalTsp % 3) * 10) / 10` で再丸め。浮動小数点誤差の二重丸めで稀に `2.97 → 3.0 → 大さじ1` 等の繰り上がり発生（テストケースで確認済み）。仕様通り「計量しやすい表示優先」だが、元の分量から見た誤差が拡大するケースがある。 | 許容誤差範囲内（料理実用上問題なし）。必要なら `toFixed(1)` 統一や有効数字制御を検討 |
| **Q-03** | Low | `parser.ts:72` | カップ単位の正規表現 `/(g|ml|cc|カップ|kg|l|L)/i` で `CC` `L` 等大文字もマッチするが、戻り値の `unit` が入力そのまま（`CC`, `L`）になる。表示上 `300CC` `1L` のまま出力される。 | 正規化（`cc`→`ml`, `l`→`L` 等）をパーサまたはフォーマッタで実施推奨 |
| **Q-04** | Low | `App.tsx:18-19` | `originalServings` / `targetServings` の初期値が `number | ''` 型で `2` / `3` だが、空文字時のフォールバックは `useMemo` 内で `> 0 ? val : 1`。入力欄クリア時に `''` が入り、計算は `1` 扱いになるが UI 上は空欄表示。ユーザーには「1人分として計算された」ことが伝わりにくい。 | 入力欄にプレースホルダ「1」表示、またはクリア時にデフォルト値復元の挙動を統一 |
| **Q-05** | Low | `App.tsx:38-49` | `useMemo` 依存配列に `recipeText, originalServings, targetServings` のみ。`parseRecipe` / `scaleRecipe` / `formatIngredient` は純粋関数なので問題なしだが、`favorites` 変更時にも再計算が発火しない（意図的）。問題ないが依存関係の意図をコメントで明示推奨 | コメント追加で可読性向上 |
| **Q-06** | Low | `theme-provider.tsx:41-54` | `useEffect` で `root.classList.remove("light", "dark")` を毎回実行。`theme === "system"` 分岐で `matchMedia` リスナ未登録のため、システムテーマ変更時の自動追従なし（手動切替のみ）。仕様に「ダークモード対応」とあるがシステム追従は未実装。 | `matchMedia` リスナ登録でシステム追従実装、または「手動切替のみ」と明記 |
